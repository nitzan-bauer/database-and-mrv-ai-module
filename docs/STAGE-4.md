# Stage 4 — Lab ingestion and the SOC schema

## ✅ Done — 22 July 2026

Six tables, applied to RDS as migration `0011`. 22 verification checks pass against the live instance.

```
labs                    the analytical laboratory
lab_imports             one ingested workbook — provenance
  ├── soc_measurements       carbon, per sample per depth
  ├── texture_measurements   sand/silt/clay — the cycle-1 characterisation
  └── import_quarantine      rows the parser rejected, and why
esm_soc_stocks          equivalent-soil-mass stock, per stratum per cycle
```

Everything except `labs` is append-only. A correction is a new row, because a VVB must be able to see the original lab value even after it has been superseded.

## Two findings from the research that changed the schema

### TOC is not a column the lab fills in

The CropNut datasheet has separate `TOC [%]`, `TOC 400 [%]`, `ROC 600 [%]` and `TIC 900 [%]` columns, which invites treating them as four independent measurements. They are not. They are the fractions of **DIN 19539 / ISO 17505** ramped combustion:

| Fraction | Temperature | What it is |
|---|---|---|
| TOC 400 | to 400 °C | Labile organic carbon |
| ROC 600 | ~600 °C | Recalcitrant organic carbon — char, soot, coal-derived |
| TIC 900 | to 900 °C | Carbonates |

So `TC = TOC400 + ROC600 + TIC900`, and true organic carbon is `TOC400 + ROC600`.

`soc_measurements.toc_pct` is therefore a **GENERATED** column, not an enterable one. Had it been enterable, someone would eventually have written TOC 400 into it, and every soil holding char would have been under-reported. That matters here specifically: residue burning is common on the farms this project serves, and burnt residue is exactly what lands in ROC 600.

A `CHECK` also enforces the identity where all four values are present, within 0.1 percentage points for rounding.

### ESM needs mass and area, not bulk density and depth

VM0042 §8.2.1.6 requires stock change on an **equivalent soil mass** basis, citing Ellert & Bettany (1995), Wendt & Hauser (2013) and von Haden (2020). The reason is that fixed-depth accounting lets a bulk-density change — caused by the very tillage practice being credited — manufacture an apparent carbon change.

Worked, on real numbers:

```
t0:  BD 1.40   TOC 1.20%   →  4,200 t soil/ha,  SOC 50.40 t C/ha
t1:  BD 1.25   TOC 1.20%   →  3,750 t soil/ha,  SOC 45.00 t C/ha

fixed depth :  −5.40 t C/ha      ← a loss that did not happen
ESM         :  +0.00 t C/ha      ← correct
```

The carbon did not move. The soil loosened, so 30 cm held 450 t/ha less of it.

`soc_measurements` therefore captures `dry_sample_mass_g` and `probe_area_cm2`. `soil_mass_t_ha` is generated from `dry_mass / probe_area`, falling back to `BD × thickness` only when the mass and area were not recorded. Without those two figures ESM cannot be computed retrospectively — and that is irreversible: if the first campaign does not record sample mass, nothing can ever be compared to it on an ESM basis.

`soc_measurements.soc_t_per_ha` still exists as a fixed-depth convenience, coarse-fragment corrected, but the auditable figure is the one in `esm_soc_stocks`. The column comment says so.

## Coarse fragments

Three columns absent from both the old datasheet and the earlier schema: `small_cf_pct` (2–10 mm, mass %), `large_cf_pct` (>10 mm, volume %), and the fine-earth `bulk_density`.

VM0042 §8.2.1.5 requires soil mass to exclude particles over 2 mm, and VMD0021 eq. 5.2 subtracts the volume held by large fragments. In stony soil, omitting this over-states stock by tens of percent. The generated `soc_t_per_ha` applies `× (1 − large_cf_pct/100)`.

## Provenance

`lab_imports` records the raw workbook URL, a **SHA-256** of the stored file, the datasheet version, who imported it and how the parse went. The raw file itself stays in the `labs` bucket, unmodified, for the project lifetime — that is the audit trail VM0042 expects.

`import_quarantine` keeps every row the parser rejected, with the original row as `jsonb` and the reason. Rows are never dropped silently; a failed import is visible rather than absent.

## Texture measurements

`texture_measurements` stores the cycle-1 characterisation, with `usda_class` generated by the same `mrv.usda_texture_class()` the strata table uses — so a stratum's class and its underlying measurements cannot diverge.

`method` is recorded deliberately: **laser diffraction reads clay systematically lower than hydrometer or pipette** and the two are not interchangeable. Mixing methods across cycles would produce a "change" that is a laboratory artefact.

## Acceptance test

Run against the live database, a full campaign from lab registration to measurement:

```
lab registered: CropNut Kenya (ISO 17025, NAPT)
work order linked to lab (FK now exists)
import recorded with provenance + sha256
  TOC400 0.90 + ROC600 0.30  →  TOC = 1.2000 %   (not 0.90)
  SOC = 23.40 t/ha   soil mass = 1,950 t/ha (from dry mass / probe area)
TC ≠ TOC400 + ROC600 + TIC900 rejected
texture 30/35/35 → USDA class = clay loam (generated)
texture not summing to 100 rejected
quarantined row kept with its reason
soc_measurements rejects UPDATE (append-only)
```

A new permanent check came out of this: where a lab reports dry mass, probe area **and** bulk density, the two routes to soil mass must agree within 15%. The first run of the test disagreed by 10× — a decimal slip in my own test data (2535 g where 253.5 g was meant), which is exactly the error a real lab would make. The check now runs on every verification.

## Outstanding

- **The ingestion pipeline itself** is application code, not schema: read the workbook, map columns, validate against open work orders, recompute SOC in the service layer rather than trusting the sheet's formula, write or quarantine. The schema is ready for it.
- **ESM computation** — `esm_soc_stocks` is the destination, but the cubic-spline interpolation of Wendt & Hauser belongs in the service layer.
- **`stratum_statistics`** — mean, SD, CV and achieved MDD per stratum. Now computable from `soc_measurements`; deferred to stage 5 with the compliance engine that consumes it.
- **`work_orders.lab_id`** is now properly constrained to `mrv.labs`, closing the stage 3 gap.
