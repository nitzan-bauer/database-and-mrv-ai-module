2  Defects found and corrected

Seven faults were found in the pre-existing engine and in work done during this phase. Each is listed with what would have happened had it shipped.

DefectConsequence if unfixedStatus
Composite floor set to 3
migration 0018		 VM0042 §8.2.1.2 requires five composites per stratum. Plans would have been generated below the methodology minimum. fixed
Three “enforced” hard checks were never implemented
migration 0019		 Same-season window, laboratory accreditation and dry combustion were documented as enforced but absent. A non-compliant cycle would have scored clean. fixed
ESM check grouped by sample, not by point
migration 0019		 0–15 and 15–30 cm are separate samples by design, so the check could never pass. Every cycle would have failed a check that was correctly satisfied. fixed
One wet parameter set applied to every farm
migration 0020		 EF_N_direct 0.013 instead of 0.005 and Frac_LEACH 0.24 instead of 0. On a 40 ha plot cutting nitrogen 30%, a claim of 7.90 tCO₂e/yr where 3.01 was due — a 162% over-statement, the direction that fails validation. fixed
Irrigation held on the parameter set, not the farm
migration 0022		 Every farm sharing a climate zone forced to share one irrigation method. Drip runs at scale across East Africa as much as Israel, so no default could be right. fixed
UNIQUE keys resting on transaction time
migrations 0020, 0021		 now() is the transaction start, so re-evaluating within one transaction collided on a constraint meant to prevent duplicate results, not duplicate attempts. fixed
Lab ingestion updated an append-only table
caught by the database		 The import record was opened, filled, then updated with totals. mrv.lab_imports refused it. Restructured to write the record once, already knowing the outcome. fixed

A naming trap was also removed. The field dry_climate_irrigated invited the answer “yes” for a drip-irrigated farm — which is irrigated — and that silently applied the wet leaching fraction, inflating the result by roughly 40%. It is now irrigation_method on the farm, with the five values the methodology actually distinguishes.

3  How the numbers are protected

ControlWhat it prevents
12 append-only tablesEvidence cannot be edited or deleted. A correction is a new row, so the record shows that a figure changed and when. This guard caught one of the defects above during development.
Refusal instead of defaultsA farm without a climate zone, or a dry-zone farm without an irrigation method, cannot be quantified at all. Guessing either would be guessing the credit volume.
Reproducible random samplingPoint placement is genuinely random, and the seed is recorded — so the draw can be repeated exactly. This separates a random sample from one re-drawn until it looked convenient.
Tokens stored as hashesA database dump yields no working field-access link. Re-sending means issuing a new token and revoking the old one.
Named actor on every write976 audit entries, each naming who acted — a person, or a token. A validation body asking why a figure moved gets a name and a time.
Verified TLS to the databaseThe connection carrying sampling and laboratory evidence verifies the server’s certificate against Amazon’s root bundle rather than disabling the check.
42 assertions in CIEvery migration applied to a clean PostGIS, fully unwound and re-applied, on every push. Includes a structural check that fails if a future UNIQUE key rests on transaction time.

Three gaps remain. None is a software gap — each is waiting on information the module cannot invent.

blocks verification		 VM0042 Table 7 requires three comparable sites within 250 km meeting nine similarity criteria. This is the one hard check currently failing, and it caps the compliance score at 85. Field work — locating comparable farms

On the failing check. Three plausible polygons could have been generated to turn QA2_3_CONTROL_SITES green. That would have fabricated precisely the evidence the check exists to demand. It is left visible, and the score reads 85 rather than 100 as a result.

5  Ready for TIER-2

The write chain was deliberately built as a tool surface rather than as form handlers. The six actions in the agent policy table are the same actions a manager performs by hand, so the Verified Credits Factory agents will call exactly what a person clicks — not a second implementation that has to be kept in step.

Agent actionModeFoundation status
propose_sampling_planautoTool built, proven on live data
send_work_orderconfirmTool built, proven on live data
run_modelconfirmTo be built in TIER-2
recalibrate_modelconfirmTo be built in TIER-2
issue_alertsautoRead-only; no write path needed
chatautoRead-only by default

Policy is read from the database rather than compiled in, so a change made in Admin takes effect immediately. An action with no policy row is refused rather than allowed — a missing policy is far more likely to be an action nobody has reviewed than one deliberately left unrestricted. A person acting directly is not subject to confirm: that mode means an agent must get someone to approve, and a person doing it themselves is that approval.

Recommended sequence

  • Now — decide who locates the three baseline control sites, and collect activity data from the grower. Both unblock a 100-scoring cycle.
  • Next — TIER-2: the agent decision layer, memory (pgvector is installed), and the two model actions.
  • Then — a second sampling cycle, which is what makes QA1 modelling possible at all.
